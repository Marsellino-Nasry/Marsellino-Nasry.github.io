01Overview

SARM is the name I use for my independent security engineering and research work. The Arsenal is its toolkit: three modules that each own one stage of an assessment.

SARM-Security maps what is exposed. VAMPIRE-X works out which weaknesses matter most. SARM-CVE-DB supplies the vulnerability intelligence both depend on.

02Problem and objectives

Problem

Scanners produce long lists rated by severity alone. A medium-rated issue that is actively exploited can matter far more than a critical one with no known exploit, but working that out by hand means cross-referencing several sources for every finding. Reconnaissance has the same problem: results arrive from many tools in many formats.

Objectives

  • Automate repeatable reconnaissance and attack-surface mapping.
  • Correlate scanner output with authoritative vulnerability intelligence.
  • Rank remediation by real-world exploitability, not severity alone.
  • Keep a local, searchable store of CVE intelligence from NVD and CISA.
  • Produce remediation insights that translate into audit-style findings.

06Implementation

Each module is a command-line tool written in Python, with Bash used for orchestration. VAMPIRE-X does not replace the scanners: it consumes their results and adds context, so findings carry their CVE details and whether CISA has confirmed exploitation in the wild.

The output is deliberately shaped like an audit finding. Each prioritised issue can be traced to the control that should have prevented it, which is how the Arsenal feeds the Dual-Lens method used in my audit work.

07Security considerations

Authorised use only

The tools are run only within written scope and rules of engagement.

Private source

The code is not publicly released, which limits misuse of the automation.

Sensitive outputs

Results describe real exposures, so they are stored and shared with the same care as audit evidence.

Authoritative sources

Vulnerability context comes from NIST NVD and CISA rather than unverified feeds.
