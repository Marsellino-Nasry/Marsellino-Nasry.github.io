Chrome Password Extractor

Security research into a common endpoint risk: passwords saved in a web browser. The proof of concept was built and run only in a lab, to support awareness and to make the case for better credential controls.

Authorised, educational use only. Accessing anyone else's credentials without explicit permission is unethical and illegal. This page covers the risk and the defences, not how to reproduce the technique.

01Overview

Browser password managers are convenient, and many employees use them for work accounts. This research looked at what that convenience costs once an endpoint is compromised, and turned the answer into awareness material and control recommendations.

02Problem and objectives

Problem

Browser-saved passwords are protected against other users and offline theft of the disk, but they are designed to be usable by the signed-in user. Malicious code running in that user's session can therefore get to them too. This is why information-stealing malware so often targets browsers, and why a single infected laptop can expose many business accounts at once.

Objectives

  • Demonstrate the risk in a controlled lab, using test accounts only.
  • Give awareness sessions a concrete, credible example.
  • Give auditors and IT teams a clear rationale for credential-management controls.

03Credential exposure chain

How a single compromised session turns into account takeover, and where each defensive control breaks the chain.

  1. Threat

    Malicious code arrives

    Typically through phishing or a malicious download.

  2. Foothold

    Runs as the signed-in user

    No administrator rights are required.

  3. Weakness

    Browser password store

    Saved passwords are usable by anything running in that session, by design.

  4. Asset

    Credentials recovered

    Work and personal accounts saved in the browser. T1555.003

  5. Impact

    Account takeover

    Access to business systems, often with no further exploitation.

Controls that break the chain

  • Awareness and trainingFewer users run untrusted code. A.6.3
  • Application control, least privilegeUntrusted code is blocked or contained. A.8.7
  • Enterprise vault, browser saving offNo credentials in the browser store to take. A.5.17
  • EDR detectionAlerts on processes reading credential stores. A.8.1
  • MFA everywhereA stolen password alone is not enough to sign in. A.8.5

04Technical approach

A short Python script, developed and run only on a lab machine against test credentials, showing that credentials saved in Google Chrome on Windows can be recovered by code running in the user's own session, using the system's encryption key. Implementation details are intentionally not reproduced on this page; the repository is published for educational review and states that it may be used only on systems where you have explicit permission.

Language

  • Python 3

Environment

  • Windows lab machine
  • Google Chrome
  • Test accounts only

05Findings

  • On the browser version studied, credentials saved for the lab user were recoverable by a script running in that user's session.
  • Nothing about the script required administrator rights, which is what makes the risk relevant to ordinary users.
  • Browser vendors continue to strengthen local credential protection, so results depend on the browser version and configuration.

06Defensive guidance

Use an enterprise password manager

Store work credentials in a managed vault with its own unlock, not in the browser.

Disable browser password saving

Turn off the built-in password manager for managed browsers through group policy or MDM.

Require MFA everywhere

A stolen password alone should never be enough to sign in to business systems.

Detect information stealers

Use EDR rules that flag unusual processes reading browser credential stores.

Least privilege and application control

Reduce the chance that untrusted code runs on the endpoint at all.

Train users

Show staff why saving work passwords in the browser is a risk and what to use instead.

Related ISO/IEC 27001:2022 controls: A.5.17 Authentication information, A.8.1 User endpoint devices, A.8.5 Secure authentication, A.8.7 Protection against malware, A.6.3 Awareness and training.
